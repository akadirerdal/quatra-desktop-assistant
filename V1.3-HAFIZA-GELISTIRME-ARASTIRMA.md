## 2. GitHub'da bulunan seçenekler

### A) Vectra — Local Vector DB for Node.js/TS (⭐ Önerilen)
- **Repo:** [Stevenic/vectra](https://github.com/Stevenic/vectra) (633 ⭐, MIT)
- **Ne:** Pinecone benzeri ama tamamen yerel, dosya tabanlı vektör DB
- **Electron desteği:** ✅ `vectra/browser` entry point (IndexedDBStorage + TransformersEmbeddings)
- **Yerel embedding:** ✅ TransformersEmbeddings — HuggingFace modeli, API anahtarı GEREKMEZ
- **Kurulum:** `npm install vectra` — native bağımlılık yok, Electron paketleme sorunu yok
- **Boyut:** Küçük index'lerde sub-ms sorgu; model ~20-50MB (ilk kullanımda indirilir)
- **Artılar:** Pure JS/TS, Electron uyumlu, local embeddings, metadata filtreleme, MIT lisans
- **Eksiler:** Küçük topluluk (633 star), tek geliştirici

### B) sqlite-vec — SQLite vektör eklentisi
- **Repo:** [asg017/sqlite-vec](https://github.com/asg017/sqlite-vec)
- **Ne:** SQLite'a vektör arama ekleyen C eklentisi
- **Artılar:** SQLite zaten yaygın, tek dosya DB, SQL sorguları
- **Eksiler:** Native extension — Electron paketleme sorunu var (GitHub issue #8824), embedding için ayrı `sqlite-lembed` gerekir, model yönetimi karmaşık

### C) Basic Memory — Local-first markdown memory
- **Repo:** [basicmachines-co/basic-memory](https://github.com/basicmachines-co/basic-memory)
- **Ne:** Markdown dosyaları ile AI sürekliliği, yerel-first
- **Artılar:** İnsan okunabilir (markdown), Obsidian uyumlu, git ile versiyonlama
- **Eksiler:** Python tabanlı (Node/Electron entegrasyonu zor), semantik arama zayıf, Quatra'nın mevcut JSON yapısına uymaz

### D) mem0 (zaten entegre)
- **Repo:** [mem0ai/mem0](https://github.com/mem0ai/mem0)
- **Ne:** AI agent'lar için memory layer, vektör DB + graph desteği
- **Artılar:** Quatra'da zaten var (`mem0-service.ts`), akıllı çıkarım, graph memory
- **Eksiler:** Yerel modu vektör DB (Qdrant/Chroma) gerektirir — ağır kurulum; bulut modu internet + API key

### E) Persistent AI Memory / MARM
- **Repo:** [savantskie/persistent-ai-memory](https://github.com/savantskie/persistent-ai-memory), [Lyellr88/marm-memory](https://github.com/Lyellr88/marm-memory)
- **Ne:** Persistent local memory, kaynak-destekli geri çağırma
- **Artılar:** Yerel-first, kaynak takibi
- **Eksiler:** Python ağırlıklı, Quatra'ya entegrasyon zor

## 3. Öneri: Vectra + Local Embeddings

**Neden Vectra?**
1. **Pure JS/TS** — native bağımlılık yok, Electron paketleme sorunu yok (V1.2-003/004 ile uyumlu)
2. **Electron desteği var** — `vectra/browser` entry point (IndexedDBStorage + TransformersEmbeddings)
3. **Yerel embedding** — HuggingFace modeli (örn. `Xenova/all-MiniLM-L6-v2`), API anahtarı GEREKMEZ, offline çalışır
4. **Metadata filtreleme** — kategori/etiket bazlı arama
5. **MIT lisans** — ticari kullanım serbest
6. **Küçük index** — sub-ms sorgu, hafıza büyüdükçe de iyi performans

**Neden mem0 değil?**
- mem0 yerel modu vektör DB (Qdrant/Chroma) gerektirir → kurulum ağır, Electron paketleme sorunu
- Vectra tek başına yeterli: embedding + vektör arama + metadata filtreleme hepsi bir arada

## 4. Mevcut sistem → Vectra ile dönüşüm

### Şu an
```
Konuşma → extraction.ts (regex kalıpları) → memory-store.json (düz liste)
Her istekte: TÜM hafıza prompt'a enjekte edilir (token israfı)
```

### Vectra ile
```
Konuşma → extraction.ts (regex + LLM çıkarımı) → Vectra index (embedding ile)
Her istekte: semantic search (top-5 relevant) → sadece ilgili hafıza enjekte edilir
```

### Kazanımlar
| Özellik | Şu an | Vectra ile |
|---|---|---|
| Arama | Anahtar kelime (regex) | Semantik (vektör benzerliği) |
| "Köpeğimin adı Max" → "evcil hayvan" sorgusu | ❌ Bulunamaz | ✅ Bulunur |
| Prompt token kullanımı | Tüm hafıza (büyüdükçe token israfı) | Sadece top-5 ilgili kayıt |
| Çelişki çözümü | 40 kalıp (sınırlı) | Semantik benzerlik ile otomatik birleştirme |
| Offline | ✅ | ✅ (local embeddings) |
| Kurulum | Basit (JSON) | Orta (npm install + model indirme ~20-50MB) |

## 5. Uygulama planı (V1.3)

### Faz 1 — Vectra entegrasyonu (1 oturum)
1. `npm install vectra` (pure JS, native dep yok)
2. `src/services/memory/vector-memory.ts` oluştur:
   - `LocalDocumentIndex` + `TransformersEmbeddings` (model: `Xenova/all-MiniLM-L6-v2`)
   - `addMemory(text, metadata)` — hafıza ekle (embedding otomatik)
   - `searchMemory(query, topK)` — semantik arama
   - `deleteMemory(id)` — silme
3. `memory-store.ts`'i Vectra'ya bağla (JSON store → Vectra index)
4. Electron main process'te index dosyası yolu: `userData/memory-index/`

### Faz 2 — Extraction iyileştirme (1 oturum)
1. `extraction.ts`'i genişlet: regex kalıpları + LLM tabanlı çıkarım (DeepSeek'e "bu konuşmadan hafıza çıkar" prompt'u)
2. Çıkarılan her kayıt Vectra'ya embedding ile eklenir
3. Çelişkili kayıtlar semantik benzerlik ile tespit edilir (shouldReplaceEntry → vektör mesafesi)

### Faz 3 — Semantic recall (1 oturum)
1. Agent loop'ta her istekte `searchMemory(userMessage, topK=5)` çağrılır
2. Sadece ilgili hafıza kayıtları prompt'a enjekte edilir
3. Hafıza listesi UI'da (SettingsPanel) semantik arama ile filtrelenir

### Faz 4 — Graph memory (opsiyonel, V1.4)
1. mem0'nun graph memory özelliği ile ilişkiler (kim kimi tanıyor, ne nerede) çıkarılır
2. Zep/Graphiti gibi temporal knowledge graph (ileride)

## 6. Riskler ve dikkat edilecekler

| Risk | Açıklama | Çözüm |
|---|---|---|
| Model indirme | İlk kullanımda ~20-50MB model indirilir | İndirme ilerlemesi UI'da gösterilsin; offline modda embedding atlanır |
| Embedding kalitesi | all-MiniLM-L6-v2 Türkçe için orta kalite | Türkçe destekli model araştır (örn. `intfloat/multilingual-e5-small`) |
| Performans | Her hafıza eklemede embedding hesaplama (CPU) | Toplu ekleme + background thread (worker) |
| Veri migrasyonu | Mevcut JSON hafıza → Vectra index'e geçiş | Bir kerelik migrasyon scripti |
| Disk kullanımı | Vektör index + model dosyası | ~100MB toplam (model 50MB + index büyüdükçe) |

## 7. Alternatif: Mem0 yerel modu güçlendirme

Quatra zaten mem0'i destekliyor (`memoryEngine: 'local' | 'mem0'`). Mem0 yerel modu şu an Qdrant/Chroma gerektiriyor. Vectra entegrasyonu yerine:

- **Mem0 + Vectra adapter**: Mem0'in vektör store arayüzüne Vectra'yı bağla → mem0'in akıllı çıkarımı + Vectra'nın yerel vektör araması
- Bu yaklaşım mem0'in graph memory ve akıllı deduplication'ından faydalanır

**Karar:** Önce Vectra'yı bağımsız dene (Faz 1-3); mem0 adapter'ı V1.4'te değerlendir.
